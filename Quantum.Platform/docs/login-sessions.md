# Persistent native-client login

`Login` retains its existing access-token response and adds `refreshToken` and `refreshExpiresAtUtc`. Access tokens retain the configured JWT lifetime. Each password login creates an independent, account-bound session with an absolute 30-day expiry. Existing clients can continue using the original fields; an old session without a refresh credential requires one new password login after its access token expires.

`RefreshLogin` accepts `{ "refreshToken": "...", "requestId": "<GUID>" }` without an access token. It returns the same response shape as `Login`, including a replacement refresh token. The server stores only token hashes, binds the session to the user's password hash, and serializes refresh/logout using the existing PostgreSQL advisory lock. Access requests carrying the new JWT `sid` are checked against the session by the common caller resolver. Logout, password reset, user deletion, and session expiry therefore invalidate subsequent access as well as refresh.

Clients persist the random refresh request ID securely before sending. A duplicate of the latest rotation with the same old token and request ID recovers the same replacement for two minutes, covering a lost HTTP response. A known consumed token used in another request, or outside this recovery window, revokes that session. Unknown tokens cannot revoke another user's session. Replacement secrets are derived with a domain-separated HMAC using the existing server signing key; no plaintext replacement is stored in the database.

`Logout` accepts `{ "refreshToken": "..." }` and revokes that session. The native clients clear local secure storage even when offline; remote revocation is best-effort when the platform is unreachable. They do not save the user's password.

Desktop and mobile use the framework-internal `PlatformSession` implementation. Credentials are scoped by normalized platform URL and kept in OS secure storage. The clients refresh before expiry, coordinate concurrent refreshes, and retry an operation once only after a definitive HTTP 401 or `authentication_required` result. A transport timeout never causes a business operation to be replayed. Network errors preserve credentials; an invalid refresh credential clears the login state and returns the UI to sign-in. Mobile restores the saved session on launch/resume and keeps device registrations and pending-operation IDs separate from login credentials.

Device access is authorized by the authenticated account. Devices in another account remain undiscoverable and inaccessible; no separate pairing approval is required. Device registration credentials retain their existing 24-hour lifetime; expiry requires reconnecting. The mobile device selector shows online desktops and an abbreviated device ID so that old same-name registrations cannot be mistaken for the current desktop.
