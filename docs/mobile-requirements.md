# NOF / Quantum 移动端需求稿

本文记录第一期 MVP 的产品范围和验收目标；开发预览的实际覆盖范围和限制见 [移动端说明](../mobile/README.md)。

本文将“NOF 移动端”理解为基于 NOF 的 Quantum 桌面插件伴随客户端；产品最终名称待定。NOF 仍是技术基础，Quantum Host、Quantum SDK 和 Quantum Platform 分别承担执行、开发契约与中转职责。

配套文档：[技术设计稿](mobile-technical-design.md)。本文替代 [旧路线图](../ROADMAP.md) 中“移动端运行远程 Web 插件”的方向；本期不建设移动端插件运行时。

## 1. 产品目标

让桌面 Quantum 插件用接近 SwiftUI 风格的 Fluent API 声明手机界面。桌面执行声明和业务逻辑，将界面数据通过 Quantum Platform 发送到手机；手机使用随应用发布的固定组件渲染，并将用户操作通过平台送回桌面。按钮等事件只能触发插件开发者预先绑定的 Quantum RPC。

移动端具备登录、设备选择、界面渲染、输入采集、缓存和传输等宿主能力，但不独立执行业务插件。桌面插件仍是业务能力、业务状态和 RPC 执行结果的权威来源。平台负责鉴权与消息中转，不运行插件业务。

首期成功场景：用户在外网手机上打开家中电脑某插件的移动页面，输入内容并点击按钮；电脑经现有插件 RPC 执行业务，手机显示结果和更新后的页面。两台设备都只需能主动访问平台 HTTPS 服务。

## 2. 已确定的边界

| 项目 | 本期要求 |
| --- | --- |
| 执行位置 | 所有插件代码、界面构造逻辑与业务 RPC 在桌面执行 |
| 移动载荷 | 版本化 JSON 界面与动作数据，不含 DLL、JS、HTML、WASM、字节码或可执行表达式 |
| 交互 | 开发者在桌面声明固定动作；移动端不提供 RPC 名称、目标或任意参数编辑器 |
| RPC 复用 | 进入现有 Quantum 插件间 RPC 通道，不另建移动业务 RPC 体系 |
| 网络 | 桌面、移动端均经 Quantum Platform 上传和轮询接收；不用直连、入站端口、WebSocket 或内网穿透 |
| 账号 | 两端都必须登录同一平台的同一账号；未登录不得上传、拉取、注册设备或执行动作 |
| SDK | 提供 Fluent API、协议校验与移动界面模拟器；.NET、TypeScript 与桌面 Host adapter 保持能力一致 |
| 发布 | 新组件或渲染能力随移动应用版本发布，不通过下发代码扩展 |

这里的“上传”是上传移动界面快照、用户操作与执行结果，不是把桌面插件包上传到手机。平台中的插件市场发布流程保持独立。

## 3. 用户流程

### 3.1 桌面开启移动访问

1. 用户登录 Quantum Platform，在桌面设置中开启“移动访问”。默认关闭。
2. 桌面注册为账号下的一台设备，用户可命名，例如“家中的电脑”。
3. 用户选择允许远程访问的已安装插件；仅展示声明了移动页面的插件。
4. 桌面在插件正常运行时发布页面目录、界面快照与在线状态。
5. 设置页显示账号、平台地址、最近同步时间、共享插件与已授权手机，可关闭共享或撤销手机授权。

允许普通平台用户使用自己已安装的插件，不要求具备插件发布者角色。声明移动页面的插件不会自动获得上传许可；用户开启共享后才上传相关页面数据。

### 3.2 手机连接与使用

1. 用户登录同一平台账号；无账号时提示在现有平台注册入口完成注册。
2. 选择一台桌面。首次连接提交访问申请，由桌面确认；同账号不能代替设备授权。
3. 展示该桌面共享的插件及页面列表，不提供移动插件市场或安装入口。
4. 打开页面，显示原生基础控件、所连接的桌面、在线状态和最后更新时间。
5. 用户修改表单草稿并点击按钮。先显示提交状态，再区分平台已接收、桌面处理中、成功、业务失败、超时或结果未知。
6. 业务成功后由桌面生成新页面；手机收到新快照后更新。用户可返回列表或切换桌面。

一台手机同时只操作一台桌面；切换后清理原桌面页面状态，不自动将命令转发到另一台电脑。同一账号可有多台手机和桌面，每个手机页面会话单独管理。

### 3.3 插件开发与模拟

1. 开发者在桌面插件内声明稳定页面 ID、组件树与动作绑定。
2. 动作绑定完整 Quantum RPC 名称及固定参数，可显式声明少量表单字段到参数的映射。
3. SDK 在开发阶段验证组件、属性、页面大小、动作与 RPC 的可用性。
4. 模拟器预览小屏、深色模式、字体缩放、加载、错误、离线和过期页面。
5. 默认使用 Mock RPC；显式切换到真实模式后，动作进入本机 Quantum Host 的同一授权网关与插件 RPC 管线。
6. 发布仍是普通桌面插件发布；移动用户无需安装对应插件包。

## 4. 第一期界面能力

采用宿主统一视觉样式，插件选择语义属性，不发送任意 CSS 或平台控件类型。

| 元素 | 最小能力 |
| --- | --- |
| Page | 标题、单页内容、宿主返回导航 |
| VStack / HStack | 顺序布局、有限间距与对齐枚举 |
| Scroll | 单一纵向滚动容器 |
| Text | 纯文本、语义字体和颜色、换行 |
| Divider / Spacer | 分隔与有限留白 |
| TextField | 单行文本、占位符、长度限制；不支持密码和文件输入 |
| Toggle | 布尔草稿值 |
| Button | 文本、启用状态、点击固定 actionId、处理中禁用 |
| Progress | 宿主或桌面给出的忙碌状态 |

首期支持页面列表进入单页、宿主返回和刷新。页面不存在、版本不支持、未共享等状态由宿主统一处理。复杂列表、图片上传、图表、富文本、手势、自定义控件、插件自定义导航和动画后续再评估。

输入只在本地形成草稿，点击按钮时一次提交；输入变化不逐键发 RPC。参数名、目标 RPC、固定字段和字段映射都由开发者声明。未声明字段不得提交；RPC 服务端仍必须校验数据和业务权限。

刷新、版本切换或会话失效时若有未提交草稿，提示用户后再丢弃；同一快照的重复投递不覆盖草稿。不同手机的草稿互不同步。第一期每个页面会话只允许一个在途动作。

## 5. 状态与故障体验

| 状态 | 用户体验与执行规则 |
| --- | --- |
| 未登录 / 登录过期 | 提示登录；不继续发送，不自动重新执行此前动作 |
| 桌面离线、休眠或心跳过期 | 显示最后同步的只读页面和时间，禁用动作；不承诺唤醒桌面 |
| 手机断网 | 缓存只读可看；点击不进入离线业务执行队列 |
| 前台恢复 | 立即轮询、重新检查设备授权和桌面状态，再获取有效页面 |
| 平台不可用 | 保留只读缓存，显示重连状态，不影响桌面插件本地使用 |
| 插件禁用 / 卸载 / 升级 | 撤销旧动作；旧页面提示不可用或需要刷新 |
| 页面过期或被刷新替换 | 拒绝旧动作，重新获取页面；不把旧点击套用到新页面 |
| 请求超时 | 显示“结果待确认”；能够查询同一请求，不自动用新请求重做 |
| 桌面执行时崩溃 | 可能已生效，显示“结果未知”；不宣称失败，也不自动重试写操作 |
| 手机退后台 | 停止正常轮询，回前台同步；本期不承诺后台实时或推送通知 |
| 撤销设备 / 退出账号 | 立即停止本机收发和执行，清除本机敏感缓存，服务端撤销设备会话 |

轮询体验定位是秒级交互，不定位为实时控制。首期只接受预计可在 30 秒内完成的动作；持续任务、流式响应和远程终端不在范围内。

## 6. 数据与授权要求

- 账号、平台实例、桌面设备、手机设备、插件运行代、页面会话共同界定权限；消息必须准确投递到原始目标。
- 桌面关闭插件共享、撤销手机或注销设备后，平台拒绝新消息，桌面也拒绝尚未执行的消息。已经产生的业务副作用不承诺回滚。
- 平台不向手机暴露桌面的全量 RPC 目录。知道 RPC 名称或 actionId 不能绕过动作绑定和运行代校验。
- 桌面上传的是面向手机的最小数据，不自动上传插件数据库、全部桌面页面或日志。
- 平台使用 HTTPS、访问控制、存储保护和过期清理。MVP 不承诺端到端加密，平台运维边界内可以接触中转内容，产品隐私说明必须明确。
- 普通诊断日志不记录令牌、输入正文、页面正文和原始 RPC 结果；仅保留必要的关联 ID、状态、耗时与错误码。
- 页面与结果短期缓存；退出账号和切换平台时清理本地缓存。具体保留时间见技术稿。

## 7. 性能与验收口径

以下为设计目标，实施时以测试环境、设备和网络条件随报告给出，不是当前实测值。

- 活跃前台默认每 2 秒轮询一次；无网络故障、RPC 小于 200ms、网络 RTT 小于 150ms 的测试条件下，按钮提交到结果显示的 P95 目标不超过 5 秒。
- 已有有效缓存时，页面本地呈现 P95 目标小于 1 秒；新会话生成到首次呈现 P95 目标不超过 5 秒。
- 支持至少 2 台桌面、2 台手机的同账号隔离测试，以及不同账号间的访问拒绝测试。
- 桌面和手机均在无入站端口、互不处于同一局域网的网络条件下完成闭环。
- 开发者能用 .NET 与 TypeScript SDK 构建相同组件和固定动作，模拟器与 Android/iOS 真机按同一协议渲染。
- 重复投递、撤权、热升级、平台重启、桌面执行中崩溃和移动进程回收都有可验证的结果语义。
- 未知控件、越限树、注入脚本、替换 RPC 目标或固定参数的载荷不能执行。

## 8. 明确不做

- 手机下载或加载 DLL、Web 插件、脚本、动态程序集和插件原生模块。
- 任意 RPC 控制台、移动端业务计算引擎、RPC 名称或模板表达式求值。
- 局域网直连、P2P、端口映射、内网穿透、WebSocket、后台常驻和推送。
- 桌面离线时执行动作，或桌面恢复后自动执行离线积压的点击。
- 跨账号共享、团队权限、插件市场、计费、业务文件传输和完整插件数据同步。
- 首期大型长任务、流式交互、复杂增量 UI diff 和跨设备协同编辑。

## 9. 发布前验证与待评审选择

本设计消除了移动端动态加载插件代码这条路径，但不等于保证 App Store 合规。Apple 的 2.5.2 涉及下载后执行代码，4.2.7 对特定远程桌面客户端规定了局域网与宿主渲染等条件，4.7 也可能影响远程软件能力的认定。平台中转、原生控件重建的本方案不能直接套用远程桌面例外；应按实际产品分类准备审核说明与可体验环境。以上为架构判断，最终以审核结果为准。[Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)（查阅：2026-10-19）。

本稿默认采用：Android/iOS 同一协议、独立 MAUI 原生渲染客户端、同账号加桌面确认授权、基础表单允许显式输入绑定、短轮询与全量快照。后续扩展应保持插件页面声明与内部移动通信之间的边界。

建议依次确认产品范围与审核路径、协议和错误语义，再进入平台中转、SDK/Host、移动渲染、模拟器与端到端验证。各阶段均须能演示完整闭环，再扩展组件范围。
